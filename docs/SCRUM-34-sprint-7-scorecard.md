## Generate the run-specific scorecard

Save the response from `GET /api/v1/rag/evaluations/runs/{run_id}` to a JSON file. Then run:

```bash
uv run python scripts/generate_sprint7_scorecard.py \
  --evaluation reports/sprint7-evaluation-run.json \
  --run-kind LIVE \
  --output docs/SCRUM-34-sprint-7-scorecard.md
```

For an offline/mocked run, pass `--run-kind OFFLINE`. To include SCRUM-122 evidence, pass `--operations reports/sprint7-operations.json` with this shape:

```json
{
  "acl": {
    "total_cases": 0,
    "passed_cases": 0,
    "unauthorized_data_exposures": 0
  },
  "latency": {
    "sample_count": 0,
    "p50_ms": 0,
    "p95_ms": 0,
    "p99_ms": 0
  }
}
```

The generated report contains quality dimensions, action-level errors, confidence distributions, proposed-threshold analysis, escalation-verification status, and ACL/latency measures when supplied. Missing SCRUM-122 evidence is explicitly shown as `NOT PROVIDED`, not treated as a pass.

## Governance

All thresholds remain `PROPOSED` until explicitly approved. The Python service cannot confirm that a downstream human ticket was created; the generated report marks escalation delivery as not verified. Do not publish the report as a completed production scorecard until the run is confirmed live and SCRUM-122 evidence has been attached.
